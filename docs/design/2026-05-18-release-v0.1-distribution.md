## 0. Summary

Ship the existing ad-hoc-signed `GmicFilter.plugin` MVP to non-developer
users on Affinity Photo 2 **and** Affinity Photo v3, without enrolling
in the Apple Developer Program for v0.1. Distribute via a single
GitHub-release zip containing the universal `.plugin`, an
`install.command` double-clickable installer that strips the macOS
quarantine bit user-side, and a short README.

> **Update 2026-05-20:** the original plan envisioned a Homebrew tap as
> the primary channel, with the GitHub-release zip as fallback (the
> "two channels, same artifact" model). Phase 0 of empirical
> de-risking (§3) finished green on the v3-compatibility front but
> revealed that Homebrew's `quarantine false` cask DSL stanza —
> on which the cask path depended for Affinity to load an
> unsigned/ad-hoc-signed bundle — was removed in late 2025, and the
> `--no-quarantine` install flag is being deprecated, with all
> non-Gatekeeper-passing casks losing support on **2026-09-01**
> (Homebrew/brew#20755, #20929). An unsigned cask therefore cannot
> be shipped now and won't work at all in 3.5 months. The design
> retains the cask scaffolding under `release/homebrew-tap/` for
> future use, but **v0.1 ships one channel only — the manual zip**.
> The Homebrew tap revives in v0.2 via the collaborator-run
> Developer ID + notarisation release pipeline. Full rationale: §12.

> **Update 2026-05-25:** v0.2.0 has now shipped through that pipeline.
> The `dstrupl/gmic-affinity` tap is live, `brew install --cask
> gmic-affinity` installs version `0.2.0`, and Affinity Photo 2 has
> been smoke-tested with the cask-installed plugin.

For v0.1, Apple notarisation, official `homebrew-cask` submission,
MacPorts, and re-enabling the cask path were explicitly deferred (§7).
As of v0.2.0, notarisation and the private tap are done; official
`homebrew-cask` submission and MacPorts remain future work.

## 1. Decisions made during brainstorming

| # | Decision                                                                                       | Why                                                                                  |
|---|------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| 1 | Ship as **v0.1.0** (keep current Cargo version)                                                 | Honest signal that this is a first public release; users should expect rough edges.  |
| 2 | **No Apple Developer Program** enrolment for v0.1                                              | $99/yr + per-release notarisation overhead is not justified until usage shows demand. |
| 3 | ~~**Primary channel: private Homebrew tap** (`dstrupl/homebrew-gmic-affinity`)~~ — **DROPPED for v0.1, see §12.** Cask scaffolding kept under `release/homebrew-tap/` for v0.2. | Brew was attractive because of one-liner install + automatic `gmic` formula dep. Homebrew's late-2025 cask DSL changes (removal of `quarantine false`) and the 2026-09-01 deadline for non-Gatekeeper-passing casks make the path infeasible without notarisation. |
| 4 | **Sole channel for v0.1: GitHub release zip + `install.command`**                              | Covers all macOS users; `install.command` strips the quarantine bit user-side, which is unaffected by Homebrew's deprecation timeline. |
| 5 | **Support both Affinity Photo 2 and Affinity Photo v3** from day one                            | User goal; Phase 0 and later manual testing confirmed the underlying plugin protocol is stable across versions. |
| 6 | **One artifact for both channels** — a single universal `.plugin` zip                          | Avoids drift between cask install and manual install; one CI build feeds both.       |
| 7 | **Empirical Phase 0** before committing to a specific cask shape                                | Two unknowns (v3 compatibility, quarantine tolerance) gate the design; cheaper to verify in an afternoon than to redesign after a release. |
| 8 | **Cargo-feature gate stays as today** (`FEATURES=live`)                                         | The release ships `FEATURES=live`; the default no-op build remains a safe fallback for developers reconciling SDK changes. |

## 2. Scope: what v0.1 ships

The release contains exactly one artifact:

```text
GmicFilter-v0.1.0.zip
└── GmicFilter-v0.1.0/
    ├── GmicFilter.plugin/        # universal, ad-hoc signed, FEATURES=live
    ├── install.command           # double-clickable installer for manual users
    └── README.txt                # 3-line manual install instructions
```

**v0.1 distribution channel (singular):**

1. **Manual install (GitHub release).** User downloads the zip from
   the project's GitHub Releases page, unzips, double-clicks
   `install.command`. The script strips `com.apple.quarantine` from
   the bundle and copies it into every Affinity plugin folder that
   exists on the user's machine
   (`~/Library/Application Support/Affinity Photo 2/Plugins/` and/or
   `~/Library/Application Support/Affinity/Plugins/`, see §3 step 2).

The `gmic` CLI runtime dependency is documented as a one-line prereq
(`brew install gmic`) in `release/README.txt` and printed by
`install.command` if the binary isn't on the user's `PATH`. This
formula dependency is unrelated to the cask deprecation discussed in
§12 — Homebrew formulae like `gmic` don't go through Gatekeeper at
all and continue to work normally.

> **v0.2 status:** the second channel is now live. The Homebrew cask in
> `dstrupl/homebrew-gmic-affinity` installs the same universal
> Developer ID-signed and notarised `.plugin` bundle into the same
> Affinity plugin folders as the manual installer.

## 3. Phase 0 — empirical de-risking

Three checks, all manual, ~one afternoon of wall-clock time. None of
the rest of the implementation should start until these resolve.

### Step 1 — Verify v2 still works (regression baseline)

Sanity check that the current `main` build still installs into
Affinity Photo 2 and runs a filter end-to-end. Establishes the
baseline before we change anything.

### Step 2 — Verify the current ad-hoc plugin loads in Affinity v3

User has v3 installed but has never tested the plugin there. Procedure:

1. Find the v3 plugin folder. The strong-prior guess is
   `~/Library/Application Support/Affinity/Plugins`. Confirm by:
   - Looking at `~/Library/Application Support/` for any `Affinity*`
     directory that isn't `Affinity Photo 2`.
   - If unclear, run v3 with `fs_usage` watching for `stat`/`open`
     calls under `~/Library/Application Support/` at startup, the
     same technique used in the original Affinity-2 plugin
     reverse-engineering (see `IMPLEMENTATION_NOTES.md` §2).
2. `make universal-install FEATURES=live AFFINITY_PLUGINS_DIR="<v3 path>"`.
3. Restart Affinity Photo v3 with a 8-bit RGB document open.
4. Confirm `Filters → Plugins → G'MIC → G'MIC...` appears and the
   picker opens.
5. Pick a known filter (e.g. `Artistic / Paint Brush`), OK,
   verify visible transformation.

**If the plugin does not load in v3**, this design's scope changes:
v3 compatibility itself becomes a separate investigation (probable
suspects: `FilterRecord` layout drift between Affinity 2 and 3, PiPL
scanner changes). The release pauses until v3 either loads or is
deliberately dropped from v0.1 scope.

### Step 3 — Quarantine-tolerance test

The empirical question that decides whether path C (brew cask) is
viable:

```bash
# Reproduce what `brew install --cask` will do.
cd /tmp
cp -R "$HOME/Library/Application Support/Affinity Photo 2/Plugins/GmicFilter.plugin" .
xattr -w com.apple.quarantine \
  "0081;$(printf '%x' $(date +%s));Safari;|com.apple.Safari" \
  GmicFilter.plugin
# Verify the bit landed:
xattr -p com.apple.quarantine GmicFilter.plugin
# Reinstall into both Affinity folders.
rm -rf "$HOME/Library/Application Support/Affinity Photo 2/Plugins/GmicFilter.plugin"
cp -R GmicFilter.plugin "$HOME/Library/Application Support/Affinity Photo 2/Plugins/"
# (same for v3 path if verified above)
```

Restart each Affinity version, check whether the plugin still loads.

**Outcomes:**

- **Both load with quarantine bit set** → path C is viable. The cask
  uses `quarantine false` (or accepts the default brew quarantine and
  documents `brew install --cask --no-quarantine` only as a fallback).
- **Either rejects the quarantined bundle** → path C is dead for v0.1.
  We ship only path D (manual `install.command`), and reopen Apple
  Developer enrolment as a v0.2 candidate. The Homebrew tap may still
  exist but will instruct users to `brew install --cask --no-quarantine`
  and clearly explain the trade-off.

## 4. Build and packaging changes

### 4.1 `make install` learns about Affinity v3

Today:

```makefile
AFFINITY_PLUGINS_DIR ?= $(HOME)/Library/Application Support/Affinity Photo 2/Plugins
```

After: a plural-valued, comma-separated default that installs into
every directory that exists, skipping the rest:

```makefile
# Comma-separated list of Affinity Plugins folders. The install target
# installs into each one that currently exists.
AFFINITY_PLUGINS_DIRS ?= $(HOME)/Library/Application Support/Affinity Photo 2/Plugins,$(HOME)/Library/Application Support/Affinity/Plugins
```

The `install` and `universal-install` targets iterate, `mkdir -p` only
into a directory whose parent exists (i.e. the Affinity app *is*
installed), and skip directories whose parent doesn't.

The legacy singular `AFFINITY_PLUGINS_DIR` keeps working — if set, it
overrides the plural list. This preserves backwards compatibility for
existing developer workflows.

### 4.2 New `make release` target

```makefile
RELEASE_VERSION ?= $(shell git describe --tags --always)
DIST_DIR        := dist
RELEASE_NAME    := GmicFilter-$(RELEASE_VERSION)
RELEASE_ZIP     := $(DIST_DIR)/$(RELEASE_NAME).zip

release: universal
        @rm -rf "$(DIST_DIR)/$(RELEASE_NAME)" "$(RELEASE_ZIP)"
        @mkdir -p "$(DIST_DIR)/$(RELEASE_NAME)"
        cp -R "$(BUNDLE)" "$(DIST_DIR)/$(RELEASE_NAME)/"
        cp install.command release/README.txt "$(DIST_DIR)/$(RELEASE_NAME)/"
        chmod +x "$(DIST_DIR)/$(RELEASE_NAME)/install.command"
        cd "$(DIST_DIR)" && zip -r "$(RELEASE_NAME).zip" "$(RELEASE_NAME)"
        @echo "Built $(RELEASE_ZIP)"
        @shasum -a 256 "$(RELEASE_ZIP)"
```

The `shasum` print is for convenience — the GitHub Actions release
workflow re-computes and embeds it in the cask file automatically.

### 4.3 `install.command`

A new top-level shell script. The whole script:

```bash
#!/usr/bin/env bash
set -euo pipefail

cd "$(dirname "$0")"
PLUGIN="GmicFilter.plugin"
if [[ ! -d "$PLUGIN" ]]; then
  echo "ERROR: $PLUGIN not found next to install.command." >&2
  exit 1
fi

# Strip Gatekeeper quarantine (added if the zip was downloaded via a
# browser). Idempotent: no-op if not set.
xattr -dr com.apple.quarantine "$PLUGIN" 2>/dev/null || true

TARGETS=(
  "$HOME/Library/Application Support/Affinity Photo 2/Plugins"
  "$HOME/Library/Application Support/Affinity/Plugins"
)

INSTALLED=0
for dir in "${TARGETS[@]}"; do
  # Only install where the Affinity app's parent dir exists (proxy for
  # "this version of Affinity is installed").
  parent="$(dirname "$dir")"
  if [[ -d "$parent" ]]; then
    mkdir -p "$dir"
    rm -rf "$dir/$PLUGIN"
    cp -R "$PLUGIN" "$dir/"
    echo "Installed: $dir/$PLUGIN"
    INSTALLED=$((INSTALLED + 1))
  fi
done

if [[ "$INSTALLED" -eq 0 ]]; then
  echo "" >&2
  echo "WARNING: no Affinity Photo install detected. Plugin not installed." >&2
  echo "Install Affinity Photo 2 or v3 first, then run this script again." >&2
  exit 2
fi

echo ""
echo "Done. Restart Affinity to pick up the new plugin."
echo "If the Filters menu does not show G'MIC, check:"
echo "  - Affinity → Settings → Photoshop Plugins → 'Allow unknown plugins'"
echo "  - 'gmic' CLI is installed: 'brew install gmic'  (G'MIC-Qt is not on Homebrew and is not needed)"
```

The script lives at the repo root, gets baked into the release zip,
and is the **only** user-visible install path for v0.1. (The original
plan kept it as a fallback to a brew cask; per §12 the cask moved to
v0.2.) The same script continues to work alongside the notarised cask
— the steps it performs (`xattr -dr` then `cp -R`) are the manual-path
equivalent of what brew does.

### 4.4 `release/README.txt`

A new file in `release/` (separate from the main repo README so it
can stay terse and not refer to features the user can't see from the
zip):

```text
G'MIC for Affinity Photo — installation
=======================================

1. Make sure the gmic CLI is installed:  brew install gmic
   (G'MIC-Qt the standalone GUI is not a Homebrew package and is not
   needed by this plugin.)

2. Double-click install.command in this folder. macOS may prompt:
   "install.command cannot be opened because it is from an
   unidentified developer." If so:
     a. Right-click install.command  →  Open  →  Open
     b. Or in Terminal:  xattr -dr com.apple.quarantine .

3. Restart Affinity Photo. Look for
   Filters → Plugins → G'MIC → G'MIC…

If the plugin is not detected, check:
  Affinity → Settings → Photoshop Plugins →
    "Allow unknown plugins to be used"  (must be ticked)

Logs: ~/Library/Logs/gmic-affinity.log
Issues: https://github.com/dstrupl/gmic-affinity/issues
```

### 4.5 GitHub Actions release workflow

New workflow `.github/workflows/release.yml`. Triggered on tag push
`v*`. Shape:

```yaml
name: release

on:
  push:
    tags:
      - "v*"

permissions:
  contents: write   # needed to create the release

jobs:
  release:
    runs-on: macos-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true
          persist-credentials: false
      - name: Toolchain
        run: |
          rustup target add aarch64-apple-darwin x86_64-apple-darwin
      - name: Build release zip
        run: make release RELEASE_VERSION=${{ github.ref_name }} FEATURES=live
      - name: Create GitHub release
        uses: softprops/action-gh-release@v2
        with:
          files: dist/GmicFilter-${{ github.ref_name }}.zip
          fail_on_unmatched_files: true
          generate_release_notes: true
```

The workflow runs after CI has already passed on the same commit
(because we only tag green commits). It uses the existing macOS
runner and the existing build chain — no notarisation step.

### 4.6 What the existing CI workflow does *not* do

The existing `.github/workflows/ci.yml` is untouched by this design.
It still builds the universal bundle on every PR and every push to
`main`. Release adds a second, tag-triggered workflow alongside it.

## 5. The Homebrew tap

>
> Per §12, Homebrew removed the `quarantine false` cask DSL stanza
> in late 2025 and is sunsetting `--no-quarantine` and all
> non-Gatekeeper-passing casks on 2026-09-01. An unsigned bundle
> cannot be distributed via brew. v0.2.0 turned the cask back on by

>
> Phase 0 step 1 + step 2 results (§3) remain valid: Affinity v2
> regression baseline PASS, Affinity v3 detection + load PASS. Only
> step 3 (quarantine tolerance) became moot.

### 5.1 Repo layout

A new GitHub repo `dstrupl/homebrew-gmic-affinity` (the `homebrew-`
prefix is mandatory for `brew tap` discovery). Contents:

```text
homebrew-gmic-affinity/
├── Casks/
│   └── gmic-affinity.rb
├── README.md
└── .github/
    └── workflows/
        └── audit.yml          # brew audit --cask on every PR
```

### 5.2 The cask file

```ruby
cask "gmic-affinity" do
  version "0.2.0"
  sha256 "2288000f1016562e8f10a19b5f38d5b86de48941546289e71415126277cfbc62"

  url "https://github.com/dstrupl/gmic-affinity/releases/download/v#{version}/GmicFilter-v#{version}.zip"
  name "G'MIC for Affinity Photo"
  desc "Photoshop-compatible filter plugin bridging G'MIC into Affinity Photo"
  homepage "https://github.com/dstrupl/gmic-affinity"

  # Runtime dependency: the plugin shells out to the gmic CLI. The
  # `gmic` formula provides exactly that. G'MIC-Qt (the standalone
  # GUI / GIMP plugin from gmic.eu) is NOT a Homebrew package — and
  # is unrelated to this plugin anyway, since the picker dialog is our
  # own native Cocoa code.
  depends_on formula: "gmic"
  depends_on macos:   :big_sur

  artifact "GmicFilter-v#{version}/GmicFilter.plugin",
           target: "~/Library/Application Support/Affinity Photo 2/Plugins/GmicFilter.plugin"
  artifact "GmicFilter-v#{version}/GmicFilter.plugin",
           target: "~/Library/Application Support/Affinity/Plugins/GmicFilter.plugin"

  caveats <<~EOS
    G'MIC for Affinity is installed for Affinity Photo 2 and Affinity v3.
    Restart Affinity to pick up the plugin.

    If Filters → Plugins → G'MIC is missing, enable:
      Affinity → Settings → Photoshop Plugins → "Allow unknown plugins"
  EOS
end
```

The original v0.1 design had two uncertainties here. Their current
status:

1. ~~**Cask DSL: two `artifact` stanzas for the same source path.**~~
   Resolved in v0.2.0: `brew install --cask gmic-affinity` accepted
   this shape and installed into both Affinity plugin folders.

2. ~~**Depending on `gmic` vs `gmic-qt`.**~~ Resolved during
   implementation: there is no `gmic-qt` Homebrew formula or cask
   (`brew search gmic` returns only `gmic`). G'MIC-Qt is a separate
   project distributed from gmic.eu. The cask depends on `gmic`, and
   README / release/README.txt / SETUP.md / install.command were all
   corrected to instruct `brew install gmic`.

If Affinity v3's plugin folder turns out to be something other than
`~/Library/Application Support/Affinity/Plugins`, the second `artifact`
target string changes. That string is the only thing in this cask that
depends on Phase 0 step 2.

### 5.3 Tap CI

A single workflow:

```yaml
name: cask audit

on:
  push:
    branches: [main]
  pull_request:

jobs:
  audit:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - name: brew audit
        run: brew audit --cask Casks/gmic-affinity.rb
      - name: brew style
        run: brew style Casks/gmic-affinity.rb
```

This is the same gate the central `homebrew-cask` repo uses on PRs.
Catching policy regressions on the tap means we won't be caught flat-
footed if we later want to submit to the central repo.

### 5.4 Per-release tap update procedure

After the collaborator-run stable release pipeline uploads
`GmicFilter-vX.Y.Z.zip` to GitHub Releases, it runs
`scripts/release-bump-cask.sh`:

1. Compute the artifact SHA256:
   `curl -sL https://github.com/.../releases/download/vX.Y.Z/...zip | shasum -a 256`
2. Update
   `version` and `sha256`.
3. Run `brew style Casks/gmic-affinity.rb`.
4. Commit and push to `dstrupl/homebrew-gmic-affinity`.
5. Users get the update on next `brew upgrade --cask`.

Optional future automation: move the tap bump into a GitHub Action if
release cadence ever justifies putting signing material in CI or
building a more elaborate secure handoff.

## 8. Risks (have a plan for each)

| # | Risk                                                                                       | Severity | Plan                                                                                                                                                          |
|---|--------------------------------------------------------------------------------------------|----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | ~~Affinity v3 does not load the current bundle at all~~                                    | ~~High~~ Resolved | Phase 0 step 2 (2026-05-19) PASS. Bundle loads on Affinity Photo 2 and Affinity v3 (3.2.1).                                                                  |
| 2 | ~~Affinity refuses to load a quarantined bundle (path C dies)~~                            | ~~High~~ Confirmed → see §12 | Phase 0 step 3 (2026-05-19) confirmed REJECT on both Affinity versions. Originally planned mitigation (`quarantine false` cask line) no longer exists in modern brew. v0.1 drops path C; ships only path D. Reopen in v0.2 with notarisation. |
| 3 | ~~The brew cask DSL doesn't accept two `artifact` stanzas with the same source~~               | Resolved | v0.2.0 cask install succeeded with two `artifact` stanzas, installing into both Affinity plugin folders.            |
| 4 | The v3 plugins folder path is not `~/Library/Application Support/Affinity/Plugins`         | ~~Medium~~ Resolved | Phase 0 step 2 confirmed `~/Library/Application Support/Affinity/Plugins/` is correct.                                                                       |
| 5 | `gmic` formula in homebrew-core is renamed / deprecated                                    | Low      | Plugin is a self-contained binary; the formula is a runtime dep documented in the manual install README, not a hard build dep. If renamed, we update the README. (G'MIC-Qt is not a Homebrew package, so a "merge into gmic-qt" scenario is not possible.) |
| 6 | First-install Gatekeeper warning on the manual path scares users away                       | Low      | `install.command` strips quarantine on itself with `xattr -dr`. `release/README.txt` documents the right-click → Open workaround as a one-time step.            |
| 7 | GitHub Actions release workflow flakes (network, runner, signing)                          | Low      | The workflow is idempotent (rerun the failed job; `softprops/action-gh-release@v2` replaces the asset if the release exists). Designed so the highest-risk pieces (§8 #1 and #2) are proven first.

1. **Phase 0 — empirical de-risking** (§3). One afternoon, no code
   changes. Resolves the two design contingencies.
2. **Both-Affinity install** (§4.1). Smallest code change; lets the
   developer flow already match the user flow.
3. **`install.command` + `release/README.txt`** (§4.3, §4.4). The
   manual install path. Unblocks shipping path D even if path C dies.
4. **`make release` + local end-to-end dry run** (§4.2). Verify the
   zip layout, the SHA256 stability, the manual install on a fresh
   user account.
5. **Release GitHub Actions workflow** (§4.5). Tag-driven release
   pipeline. First tag: `v0.1.0-rc.1`, exercises everything.
6. **Documentation refresh** (§6). README restructure, PRD update,
   IMPLEMENTATION_NOTES.md §11.
7. **Homebrew tap repo + cask file + tap CI** (§5). Land alongside
   the first real `v0.1.0` tag.
8. **End-to-end install verification on a fresh Mac account** —
   manual; one paragraph of notes appended to the implementation
   plan's self-review section.

Milestones 2–4 can begin even if Phase 0 step 3 (quarantine
tolerance) hasn't been run yet. Milestone 7 hard-depends on Phase 0
step 3 because the cask shape changes based on its outcome.

## 12. Postscript — why the brew cask path was dropped from v0.1

The Phase 0 step 3 **observation** (Affinity rejects quarantined
bundles) is correct and reproducible. The original Phase 0 step 3
**decision** ("add `quarantine false` to the cask, path C survives")
was based on Cask DSL documentation that ceased to be accurate
between the time this design doc was written (2026-05-18) and the
moment we tried to execute it (2026-05-20). This section records
exactly what changed and why we changed course, so the next
implementer (us in v0.2, or someone reading this in 2027) doesn't
re-derive it from scratch.

### What Homebrew did upstream

Three relevant changes, all in late 2025:

1. **`quarantine false` cask DSL stanza removed.** Verified by
   reading `/opt/homebrew/Library/Homebrew/cask/dsl.rb` on
   Homebrew 5.1.11 — there is no `def quarantine` accepting a
   bareword argument. The reference docs only describe a
   command-line `--quarantine` / `--no-quarantine` flag.
2. **`--no-quarantine` install flag deprecated.** [Homebrew/brew
   #20929 (Oct 2025)](https://github.com/Homebrew/brew/pull/20929)
   removed the flag from documentation, man pages, and shell
   completions; current versions still accept it but emit a security
   warning to the user on every install. Confirmed in
   `/opt/homebrew/Library/Homebrew/cask/installer.rb:163`:
   `opoo_outside_github_actions "--no-quarantine bypasses macOS's
   Gatekeeper, reducing system security."`
3. **Hard cutover: 2026-09-01.** [Homebrew/brew
   #20755](https://github.com/homebrew/brew/issues/20755) —
   "Removing support for `--no-quarantine` for casks." Quoting the
   issue: "we are ending support for all casks that fail Gatekeeper
   checks on September 1st, 2026." That is **~3.5 months from now**
   (today 2026-05-20).

The v0.1 Homebrew design predates all three changes. The
`quarantine false` line we wrote was a workaround for an unsigned
bundle — exactly the workflow that's being deprecated.

### How it surfaced

We first noticed at the local cask smoke-test step (Option C in the
release plan): the throwaway cask pointed at `v0.1.0-rc.1`, real
SHA256 pinned, run via `brew install --cask` against a scratch tap.
The install failed instantly:

```text
Error: Cask 'gmic-affinity' definition is invalid:
  undefined method 'quarantine' for Cask 'gmic-affinity'
```

Source-grep on `/opt/homebrew/Library/Homebrew/cask/` confirmed the
DSL method had been removed; web search for "homebrew cask DSL
quarantine false removed" surfaced #20755 and #20929 above.

### What we considered

Four options, in declining attractiveness:

1. **Drop path C from v0.1, ship path D only. Resurrect path C in
   v0.2 with notarisation.** — chosen.
2. Pause v0.1 to do Apple Developer enrolment + notarisation now.
   Rejected: one-week-plus slip + $99/year + per-release notary
   pipeline work. Outsized cost for a v0.1 nice-to-have.
3. Ship path D in v0.1 now; cut a follow-up v0.1.1 with the cask
   once notarisation is wired up. Acceptable; superset of (1).
   Defer the "should this be v0.1.1 or v0.2?" decision until we
   actually do the notarisation work.
4. Ship the cask anyway with `--no-quarantine` install instructions.
   Rejected: gives the user a security-warning-printing install path
   that breaks fully in 3.5 months and conflicts with Homebrew
   maintainer policy.

### What changed (v0.1 final)

| File | Change |

### What we'd do differently

Two design-process notes, recorded for the next time we plan a
distribution change:

1. **Verify upstream-API assumptions empirically before committing
   to them in a design doc, not just by reading vendor docs.** A
   30-second `brew install --cask` against a scratch cask before
   §5.2 was finalised would have caught the DSL change immediately.
   Section 3 of the design doc does this for Affinity (Phase 0
   step 3) but not for Homebrew. Phase 0 should always include
   "execute the dependency at least once with a placeholder
   payload" for every external system in the critical path.
2. **Watch for upstream policy timeboxes.** The `quarantine` DSL
   removal didn't come out of nowhere — it was telegraphed in
   announcements 6+ months in advance. Adding "Apple-side and
   distribution-side deadlines" to the regular doc-review checklist
   would catch this.
