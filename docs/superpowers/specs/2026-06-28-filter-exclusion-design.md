# Hide unusable filters from the picker — design

Date: 2026-06-28
Status: Approved (brainstorming), pending implementation plan

## Goal

Stop showing filters the plugin cannot meaningfully run. The G'MIC
catalogue (~1197 filters after the existing `_`-prefix prune) includes
filters that cannot work as a single-image, non-interactive transform
with default parameters: multi-input (blend/merge/compositing),
interactive (need live user input), and external-data / non-filter
utility entries. These should be **hidden entirely** from the picker
tree so users only see filters that actually work.

## Scope

- **In scope:** exclude (hide) unusable filters from the picker.
- **Out of scope (deferred):** passing the user's selected region /
  selection to filters so that selection-dependent filters become
  usable. Captured as a separate feature request
  (`docs/feature-requests/region-passing.md`).

## What counts as "unusable"

A filter is excluded if EITHER signal applies (hybrid):

1. **Empirical (baked list):** the preview generator could not render it
   for a *structural* reason — it needs a second input image, live
   interaction, an external/selection input, or otherwise cannot produce
   output from one image with defaults.
2. **Heuristic (in-code):** static rules over the catalogue catch the
   same structural classes by command name / metadata, as a backstop for
   filters the baked list might miss or when previews were never
   generated.

**Transient failures are NOT exclusions.** Build-time skips with a
*transient* reason — `timeout after Ns`, `filter arg is N bytes (max N)`
— are kept visible: a filter that timed out on the build machine may
still be usable on a smaller image. The emit step (below) filters skip
reasons so only structural-unusable filters land in the baked list.

## Architecture & data flow

```
gen-previews  --(render pass)-->  manifest.json (local, gitignored)
      |  --emit-exclusions (structural skips only)
      v
assets/excluded-filters.txt   (COMMITTED, ships in every build)
      |  include_str!
      v
catalogue::builtin()  --prune-->  Catalogue (excluded filters + empty folders removed)
      ^
      |  is_excluded_by_heuristic(command)  (in-code backstop)
```

Two units, both pure/testable:

- **`src/catalogue/exclusion.rs`**
  - `pub fn is_excluded_by_heuristic(command: &str) -> bool` — pure,
    table-tested static rules.
  - `pub fn baked_exclusions() -> &'static HashSet<String>` — parses the
    committed `assets/excluded-filters.txt` (via `include_str!`),
    ignoring `#` comments and blank lines, cached in a `OnceLock`.
  - `pub fn is_excluded(command: &str) -> bool` —
    `baked_exclusions().contains(command) || is_excluded_by_heuristic(command)`.
- **Pruning** in `catalogue::builtin()` — after `parser::parse`, walk the
  tree once: drop every `Filter` whose command `is_excluded`, then drop
  folders left empty (recursively, so a folder containing only excluded
  filters disappears). Deterministic, single pass.

This extends the precedent already in the parser (`is_gmic_qt_only`
skips `_`-prefixed commands); exclusion is the same idea, applied
post-parse with a richer source.

## The committed exclusion list

`assets/excluded-filters.txt` — committed plain text, sorted, one gmic
command per line, with a header:

```
# Filters excluded from the G'MIC picker because they cannot run as a
# single-image, non-interactive transform with default parameters.
# Generated by `gen-previews --emit-exclusions` from the preview render
# pass (structural skips only; timeouts/transient failures are NOT
# listed so they stay visible). Regenerate after a catalogue or gmic
# update. See docs/superpowers/specs/2026-06-28-filter-exclusion-design.md
fx_blend
fx_clut_from_ab
...
```

Committed (unlike the previews themselves) because it is tiny and MUST
ship in every build, including builds where `make previews` never ran.

### Generator emit step

`gen-previews` gains `--emit-exclusions <path>` (and a `make
excluded-filters` / step within `make previews`). It writes the file
from the manifest's `skip` entries, **filtering by reason**: include
structural reasons (anything that is not a timeout or arg-length cap),
exclude transient ones (`timeout after`, `filter arg is … bytes`). The
output is sorted and de-duplicated for a stable diff.

## Heuristics (the static backstop)

`is_excluded_by_heuristic` is a small, well-commented set of
conservative patterns seeded from the empirically-measured skip set:

- **Interactive:** command ends with `_interactive`, or is in a known
  set (`MorphoPaint`, `morph_interactive`, `curves_interactive`,
  `colorize_interactive`, …).
- **Multi-input / compositing:** known commands that need a second image
  (`fx_blend`, `fx_blend_fade`, `fx_clut_from_ab`, `fx_transfer_pca`,
  `fx_layer_cake`, `fx_layer_cake_2`, …).
- **External-data / non-filter:** `gui_download_all_data` and similar
  utility/UI entries that are not image transforms.

Heuristics are deliberately NOT exhaustive — the baked list carries the
long tail. They exist so the common structural classes are hidden even
in a checkout where previews were never generated.

## Error handling

- If `assets/excluded-filters.txt` is missing or unreadable at compile
  time, `include_str!` fails the build — acceptable, since the file is
  committed and required. (No runtime file I/O.)
- Pruning never removes a filter that isn't excluded; a malformed line
  in the list (no whitespace/`#`) is treated as a literal command and
  simply won't match anything real.

## Testing

- **`is_excluded_by_heuristic`**: table tests per class (interactive /
  multi-input / external) plus negatives (`fx_old_photo`, a normal blur
  are NOT excluded).
- **`baked_exclusions`**: parses the committed file; `#` comments and
  blank lines ignored; a known listed command is present, a known-good
  one absent.
- **Pruning**: fixture catalogue with a mix → excluded filters removed,
  normal filters kept, folders emptied by exclusion removed, non-empty
  folders retained.
- **Common-path guard**: a handful of well-known filters
  (`fx_old_photo`, a standard blur, etc.) survive pruning over the real
  `builtin()` catalogue — we never over-prune the everyday filters.
- **Emit step**: given manifest entries with mixed reasons, the emitted
  list includes structural skips and EXCLUDES timeout/arg-length
  (transient) skips.
- **Sanity-bound test (anti-cripple guardrail)** over the real
  `builtin()` catalogue:
  - Excluded count is within a band, not an exact number (an exact
    count is brittle against legitimate small catalogue changes):
    **excluded ≥ ~50** (lower bound — if exclusions collapse toward
    zero, the baked list failed to load or heuristics broke) and
    **excluded < 20% of total filters** (upper bound — a routine
    catalogue/gmic upgrade must not silently hide a large fraction).
  - **kept > 950** absolute floor on surviving filters.
  - The band edges carry a comment: they are deliberate guardrails to be
    bumped *consciously* when a catalogue change legitimately shifts the
    numbers, never adjusted silently to make a surprised test pass.
  - These `builtin()`-backed tests require the Git-LFS catalogue asset to
    be hydrated (same precondition as the existing catalogue tests); they
    run in the normal `cargo test` suite.
